# 行为手册（现象 → 解法）

只写"你会看到什么、然后怎么做"。按你正在做的事分组。

> 加载时机：已经有报错、生成结果不对、加载异常、或时钟目标解不出来时。一切正常时不用读本文件。
>
> 段索引：一、编译报错；二、对拍变红；三、生成问题；四、RTOS 与中间件；五、时钟与拓扑查询；六、家族差异与环境。直接跳到对应段。

## 一、编译（ioc build）报错

| 现象 | 就这么做 |
|---|---|
| 报 unknown，说某参数"不属于当前模式" | 参数清单随模式变。先把 `ips[].mode` 写对，再对照报错里给的可用参数名。 |
| 报 unknown，说引脚上没这个信号，或说信号有多个模式 | 引脚信号名取自器件定义，可能是复合名（例如 `PA0-WKUP`）。有多个模式时，在 `pins[]` 里显式给 `mode`。 |
| 报 unknown，说"查不到实例" | 器件里没有这个外设实例（例如 F103 没有 SPI3）。换实例或换器件。 |
| 报 unsupported，说 RTOS 对象表的某个类别 | 对象表支持 Tasks / Queues / Mutexes / RecursiveMutexes / BinarySemaphores / CountingSemaphores / Timers。事件组只在 CMSIS_V2 下支持。写了未知类别或 CMSIS_V1 事件组才报这个。 |
| 报 target，说"不认识的字段" | 目标里有拼错或未支持的字段。报错会列出这个版本支持的字段。 |
| 报 conflict，说同一根脚两个信号 | 目标里两处冲突。改目标。 |
| 报 unknown，说时钟解不出 | 目标频率在当前时钟树下没有精确解。先读第五节，用 `probe clock` 看拓扑；再改目标频率或显式给 RCC 参数。 |
| 不知道芯片有哪些外设实例名 | `probe peripherals --device <器件>` 列全部实例（B1）。`instance` 直接抄，不要自己拼。 |
| 报错附了"Did you mean (...)"，能直接用吗 | 那是建议，不会自动生效。按括号里的查询域核对，然后用正确名字重写（B4）。 |
| 写 `pins[]` 前不知道信号能落哪些脚，或一个脚挂着多个信号 | `probe pins --ip <实例> --device <器件>`（B3）；有 `--mode` 时看该模式必需信号与候选脚。`conflicts`=两个信号抢同一脚，`missing`=器件 XML 没给候选脚（判不了，不是不用接）。 |

## 二、对拍变红（`ioc check`，开发 / 验收用；发布不需要）

| 现象 | 就这么做 |
|---|---|
| 丢键，且丢的是 `Mcu.IP<n>` | ① 少写了宿主外设（例：USB_DEVICE 要同时给 USB 设 Device）。② 外设只给了半个模式（USART 异步只写 TX 不写 RX，整个实例会被丢掉）。 |
| 丢键，丢的是某个参数 | 那个参数不在当前模式的清单里。先确认模式，再确认参数名。 |
| 值不一致（`NVIC.*` 抢占优先级被改大） | 用了 RTOS：低于 `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY` 的会被抬到下限。跟着写。 |
| 日志里有 `Invalid parameter (Events01)` | 事件组参数是插件运行时创建的。属已知噪音，生成正常。 |
| 日志里有 DMA 的 `Parameter ... currently not set` | 噪音。CubeMX 自己保存的文件重新加载也会打。 |

## 三、生成（ioc generate）出问题

| 现象 | 就这么做 |
|---|---|
| 根目录没有 `startup_stm32*.s` | 多半是器件名写错。先 `probe describe` 核对器件 RefName。 |
| 生成失败，提示缺固件包 | 目标家族的固件包没装。先去 CubeMX 里下对应包。 |
| 生成时弹出模态框、命令行卡住 | 用工具跑（它会临时抑制弹框）。自己起会话的才会卡。 |
| 生成成功，但某个数值没出现在生成的代码里 | 那个参数可能不是生成代码里的常量（例如时钟频率名）。检查判据是否选对了键。 |

## 四、RTOS 与中间件

| 现象 | 就这么做 |
|---|---|
| 生成时报 `defaultTaskName` 为空，或模板失败 | 少了默认任务表。工具会自动补 `FREERTOS.Tasks01`；自己拼 .ioc 时会漏。 |
| 想知道 RTOS 初始化在哪个文件 | 这个版本**没有** `MX_FREERTOS_Init`。初始化写在 `Src/main.c`（`osKernelStart` 与默认任务句柄），`Src/freertos.c` 是空壳。 |
| 想知道 RTOS 堆大小在哪 | 在 `Inc/FreeRTOSConfig.h` 的 `configTOTAL_HEAP_SIZE`。目标里给这个参数，堆大小就跟着变。 |
| USB 类启用了但生成不出来 | 要两段：宿主控制器（USB 设 Device，或 USB_OTG_FS 设 Device_Only）+ 类（USB_DEVICE 设 CDC_FS 之类）。USB 全速还要 48 MHz。 |

## 五、时钟与拓扑查询

| 现象 | 就这么做 |
|---|---|
| 时钟目标报 unknown，理由写 exhausted | 支持范围内能搜的都搜过了，包括超上限。读理由里写的上限或冲突参数。 |
| 时钟目标报 unknown，理由写 truncated | 搜索预算被截断，**没有证明**解不出来。先看理由里的候选上限，必要时改用显式 RCC 参数。 |
| 时钟目标报 unknown，理由写 unsupported | 这种结构没建模。不要当成"硬件不行"。 |
| 小数 PLL（H5/H7）目标报 exhausted，理由提到"分数分辨率" | 该目标需要 `N + F/8192` 表达不了（例如需要 `F=8192/3`）。换目标频率，或把该 PLL 的 FRACN 显式写成能表达的值。 |
| 多目标时钟报"最终 RCC 参数不满足目标"或"固定参数冲突" | 联合求解后会用最终参数独立重算每个目标。要么两个目标物理上冲突（例如 HCLK 小于 APB），要么显式给的分频/源/FRACN 与目标冲突。按提示改。 |
| 想知道某个频率由哪些元件算出来 | 运行 `probe clock --device <器件> --view upstream --output <读数>`。返回里有全部上游（MUX 的每个分支、小数倍频的分数输入都在），以及每个元件的参数绑定。 |
| `probe clock` 报"没有匹配元素" | 读数名在这个器件上不存在，或读数是 MP2 这类不同命名。改用元素 id（`--view graph` 里能看到）。 |
| `probe clock` 的连接里出现 `candidates` 或 `unresolved` | 原始 XML 里这个引用不唯一或找不到目标。按候选核对；不要自己挑一个当答案。 |
| 查询返回里元素带 `unmodeled_type` | 这个元素类型没有解释语义（`xbar` 等）。只看连接与属性，不要假设它等价于 MUX。 |
| 目标里写了时钟参数，但 .ioc 里"丢"了键 | `.ioc` 只写和默认值不同的键。键不在不等于丢。先确认它是不是等于默认值。 |

## 六、家族差异与环境

| 现象 | 就这么做 |
|---|---|
| 换了一个家族，参数名或时钟名对不上 | 已知边界：F1/F4/H7/C0 做过原生加载验收（抽样矩阵），L4 只到 L0/L1；四个家族的时钟目标都覆盖（C0 无 PLL，走纯分频路径）。家族间参数名、时钟输出名可能不同（例：F407 时钟树里没有 `USBFreq_Value`）。报 unknown 就按报错里给的可用名改。 |
| 换机型后某键"丢"了 | 见第五节最后一行：等于默认值的键不写。 |
| `machine.json` 报错 | 本机配置缺失。按报错填 `cubemx_home`；要生成代码时再填 `repository`。 |
